# Example: Architecture Whack-a-Mole

## 输入

> Agent 又选错工具了。上次加了关键词规则，这次用户换了说法，又走错了。我们再补几个 trigger？

## 失败模式

Patch Spiral / Wrong-Layer Fix

## 如果继续补丁化

团队会继续加：

- 更多关键词
- 更多正则
- 更多 prompt 禁令
- 更多 if/else 分支

短期能修一个 case，长期会让 router 变成不可解释的补丁堆。

## 使用大道至简 Skill

先回答：

1. 这个问题出现过几次？
2. 判断逻辑分散在几个地方？
3. 有没有客观 eval？
4. 上次修复是否让别处变差？

如果同类错误反复出现、判断逻辑开始扩散，这就不再是单点 bug，而更可能是 Routing / System Boundary 层缺少正确机制。

## 更好的下一步

- 定义工具选择的输入契约。
- 建立 router eval：正例、反例、边界例、回归例。
- 把关键词从主要判断逻辑降级为辅助特征。
- 增加 verifier 检查所选工具是否匹配用户目标。

目标不是补上这一句话，而是让**同一类表达变化不再击穿系统**。
